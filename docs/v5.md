## Required Remediations by Criterion

### 1. Logging Consistency (Gateway & Planner)
- Replace raw `process.stdout.write` startup logging with `createLogger` in Gateway and Planner to match the shared observability pattern used elsewhere.【F:packages/gateway/src/server.ts†L11-L63】【F:packages/planner/src/server.ts†L17-L129】【F:docs/v3b.md†L3-L9】
- Extend Gateway/Planner coverage with unit tests that assert log forwarding when services boot and when downstream calls fail, mirroring existing MCA logger usage.【F:packages/mca/src/server.ts†L15-L195】【F:docs/v3b.md†L3-L20】

### 2. Configuration Externalization & Startup Guards
- Remove hardcoded database and MinIO credentials from the shared env loader and introduce a production-only guard that exits when weak defaults or missing secrets are detected.【F:packages/shared/src/env.ts†L15-L25】【F:docs/v3b.md†L10-L20】
- Enforce `OPENAI_API_KEY`, Langfuse secrets, and MinIO credentials at boot via explicit checks instead of silent empty-string fallbacks.【F:packages/shared/src/env.ts†L20-L26】【F:docs/v3b.md†L10-L20】

### 3. Error Handling & Negative Tests
- Add defensive try/catch blocks and negative HTTP tests for the Runner to cover invalid payloads, sandbox failures, and artifact write errors (currently only a happy-path test exists).【F:packages/runner/src/server.ts†L14-L25】【F:packages/runner/src/__tests__/server.test.ts†L1-L60】
- Augment Validator tests to simulate missing `execId`, absent code files, and unset `E2B_API_KEY`, asserting 400/500 responses without depending on Redis connectivity.【F:packages/validator/src/server.ts†L56-L214】【F:docs/v3b.md†L15-L22】

### 4. Secrets Scanning (Sustain PASS)
- Preserve existing regex suite and unit coverage that currently deliver a PASS; capture regression tests to ensure new paths (e.g., multi-file sandbox writes) remain scanned.【F:packages/validator/src/server.ts†L20-L214】【F:packages/validator/test/expanded-coverage.spec.ts†L41-L171】

### 5. Coverage Threshold Enforcement
- Raise global coverage above 80% by prioritizing untested branches in shared utilities and MCA flow controllers, then persist the result through the existing `check-coverage.ts` gate.【F:scripts/check-coverage.ts†L1-L56】【F:docs/v3b.md†L29-L35】
- Unblock validator coverage runs (mock Redis or provide lightweight fixtures) and wire `npm run test:validator` plus `npm run compliance:validator-coverage` into CI so the 90% requirement executes on every build.【F:package.json†L8-L33】【F:.github/workflows/ci.yml†L53-L98】【F:docs/v3b.md†L29-L35】

### 6. MCA Remediation Loop (Sustain PASS)

### 7. Artifact Provenance

### 8. Operational Readiness

## Evidence Automation & Traceability

### Pipeline Commands
- Follow the mandated binary gates—`npm run lint`, `npm run typecheck`, `npm test` with ≥80% coverage—and re-run until all succeed, storing outputs under `.automation/evidence/$TASK/valid/`.【F:AGENTS.md†L40-L171】
- Record validator-specific coverage enforcement by executing `npm run test:validator` and `npm run compliance:validator-coverage` once Redis dependencies are mocked or containerized for CI stability.【F:package.json†L18-L33】【F:docs/v3b.md†L29-L35】

### Automated Report Generation
- Add `scripts/validate-production-readiness.sh` (and supporting `scripts/tools/*.mjs`) to orchestrate logging checks, env-guard assertions, health probes, coverage enforcement, secret scanning, checksum verification, and final report synthesis, persisting artifacts under `.automation/evidence/v5/`.【F:AGENTS.md†L83-L146】
- Build a reporter (`scripts/reporters/build-v5-report.mjs`) that outputs both JSON and Markdown with embedded git metadata (`repo_remote`, `branch`, `commit`, `tree`) captured via `git rev-parse`, satisfying provenance expectations already outlined for evidence capture.【F:AGENTS.md†L110-L121】

### Snippet Provenance Requirements
- For every quoted code excerpt in the v5 report, compute and record the source `blob_sha`, line range, and `sha256` of the excerpt text alongside the claim so reviewers can independently verify authenticity.【F:docs/v2.md†L574-L662】【F:AGENTS.md†L51-L146】
- Store artifact hashes (changed files, generated reports, Playwright captures) in `.automation/evidence/v5/artifacts.sha256` and link them from the report summary, extending the existing evidence discipline.【F:AGENTS.md†L83-L146】【F:docs/v2.md†L589-L662】
